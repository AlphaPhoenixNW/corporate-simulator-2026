# Corporate onboarding | NOTHING™

Thank you for considering a strategic allocation of your time. Contributions should make the real game more reliable, accessible or enjoyable, even when its fictional management would object.

## Before proposing an initiative

Read the [governance](docs/GOVERNANCE.md), [project brief](docs/PROJECT_BRIEF.md), [architecture](docs/ARCHITECTURE.md) and [current status](docs/STATUS.md). Check [publication review](docs/PUBLICATION_REVIEW.md) for current licensing and contribution permissions before distributing or submitting material.

## Operational incident submissions

Include the version, browser/device, reproduction steps, expected behaviour and actual behaviour. Where useful, include a seed and a sanitised save or screenshot. Do not include credentials, personal data or private source material.

## Strategic transformation proposals

Describe the player problem, proposed outcome, affected mechanics and acceptance criteria. Keep scope narrow. Do not replace a deterministic simulation with a real paid service.

## Verification

Use Node 22.12+ and npm ci. Run the checks in [README.md](README.md), add tests for rule changes and preserve saved-game compatibility. Keep accessibility, mobile layout, keyboard operation and reduced motion intact. Do not claim a check passed without evidence.

The [working agreement](AGENTS.md) governs implementation. Owner approval is required for publication, licensing and release decisions.

A meeting is not required to submit an adequately documented change.
